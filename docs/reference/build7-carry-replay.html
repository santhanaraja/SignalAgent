SignalAgent · Build 7 · extension-guard carry replay

The guard question closes — and the binding constraint turns out to be capacity, not selection

Build 5.1 named the extension guard as the doctrine's most expensive row: the days it excluded earned 1.43% against A+'s 0.83%. This study asked whether that survives once real stops, sizing and ceilings are applied. It does not — and the reason is more interesting than the verdict.

1 · Two verdicts, read mechanically against the pre-written table

Four arms in a 2×2 — guard on/off crossed with fixed 6.5% sizing versus risk-parity. Everything else held identical: the same stop, the same fills, the same costs, the same caps, the same score-order selection.

The prediction made before the run was half right. Branch 4 for the guard — correct. And branch 5, sizing, was named in advance as where the real chance of a finding lay. There is one. It is the exact negative of the one expected: risk-parity, proposed in deliberation as the fix for the accidental risk spread, is measurably worse than the fixed sizing already in production.

2 · Why the guard couldn't matter — the capacity finding

Removing the guard was expected to admit a much larger population. It admitted a much larger population and produced fewer trades. That contradiction is the study's real result.

This is a better answer than "inconclusive." A null result normally leaves you wondering whether the effect is absent or merely unmeasurable. Here the trade counts explain it: the guard could not have mattered, because the constraint it operates on was never the one binding. Populations do genuinely differ — Jaccard overlap 0.523 — they simply are not larger where it counts.
And it redirects the whole programme. The open question stops being "which entry rows should gate?" and becomes "what should sizing and the ceiling be?" That is Build 6B's territory, and it now has a measured reason to exist rather than an intuition.

3 · The study stopped itself first — and found two committed results were already false

Before any performance number was read, the integrity gate failed. The pre-registration said "cent-exact, or stop." It stopped.

whatfinding
The gate failure S1 returned 14.11% / $235,787.28 against 5B's committed 14.06% / $235,200.09 — same 1,068 trades, same drawdown, $587 apart.
The cause 5B's panel builds its group map from public/universe_ranking.json — an artifact the weekly rotation rewrites. The Aug-8 rotation moved three tickers between sub-industries, so R28's group caps bound on different days and the equity path shifted while the trade count did not. Small enough to have gone unnoticed indefinitely.
Blast radius Build 6A was affected too — it now fails its own gate identically. Layer A and 5.1 are clean on this input; they never read the group map. Two committed study results had been quietly non-reproducible since Saturday.
The discipline The map was not pinned inside Build 7 to make its own gate pass. Doing so would have resolved, after seeing a number, an ambiguity that was made a stop condition precisely so it could not be.
The general lesson, and it has a name now. A pin anchored to something that moves stops testing what it was written to test. Yesterday that arrived on a study's anchors — a sliding twenty-commit window. Today it arrived on a study's inputs — a live artifact read at run time. Same family, different surface. Anchor to a fixed commit or a content hash; never to a position in a moving sequence, and never to a file something else rewrites.

4 · The sibling sweep — one study was already broken and passing

"Clean on the group map" is not "clean." Every input of every committed study was enumerated and classified.

Recorded-but-unasserted rot. A number printed in a report that nothing checks, decaying quietly while the suite prints green. Layer A's companion bridge figure had degraded from "129 of 130" to raising bridge too thin: 0. Both are now pinned to explicit commits and both reproduce their reported figures exactly.
And the second finding is the more uncomfortable one. Layer A — the foundation of the entire evidence base — survived on a single aggregate pin rather than per-input pins. Nine of its inputs are live. What saved it is a frame-rebuild anchor that has a --fast bypass, is not run automatically, and cannot name which input moved when it trips.
The fix: one manifest of asserted content hashes, checked at each study's real entry point, raising with the name of the input that moved. Wired into all five studies. The price cache is hashed over filename and content, because the directory listing is the study population. Two things were left unpinned on purpose, with reasons recorded: the live import of production grading code — that coupling is the point, not a defect — and the dependency floors, which are a repo-wide decision rather than a study one.

5 · What this changes

  1. The extension guard stays, and the question is closed. Build 5.1's finding was real at signal level and does not survive at system level. That is now five separate occasions on which a raw-return finding in this project failed to transfer once stops were applied — the pattern is no longer a coincidence, it is a property of the technique.
  2. Fixed sizing stays, on stronger evidence than expected. Risk-parity was proposed in deliberation, partially retracted on arithmetic, and is now measured as worse by 4.41 CAGR points with a CI excluding zero. The idea is dead. The plan currently being executed — eight names at a fixed percentage — is the arm that won.
  3. The programme redirects from selection to capacity. If the book is capacity-bound, the levers that matter are the ceiling and the sizing, not which rows gate entry. Build 6B inherits a measured reason to exist.
  4. Every committed study now fails loudly rather than drifting. That is worth more than any single verdict: five studies, thirty-eight inputs, one manifest, and a failure that names what moved.

What this does not settle

One window, and v1 grades. The study runs on the v1 scorer for comparability with 5B and to satisfy its own integrity gate. Production has run v2 since 9 August. The transfer of this conclusion to v2 grades is an assumption, not a finding.

The pre-registration contained a real defect. Its paired per-trade R bootstrap was structurally blind to sizing — R-multiples are share-scale invariant, so shares cancel and the test could not detect the thing it existed to test. Caught by the implementer before any performance number was read, amended on the record with the original clauses left intact above it, and the provenance noted plainly.

Risk-parity could not always fund itself. Tight stops push size to the cap, and concurrent capped positions exhaust cash. Shares clamp to affordable so the trade survives and the pairing holds; the clamp binds on 9.4% and 5.3% of trades and is reported as a validity number, not hidden.

Slippage is not modelled. 5B measured 32–37% of stop exits filling below the entry stop. That penalty falls hardest on the wider-stop trades the no-guard arms admit — so those arms are flattered, which makes the no-adoption verdict stronger rather than weaker.

One follow-up earned and not taken. The doctrine study's comment declares it "frozen to the v1 ladder" and imports a v1 function to that end — but the import is dead and the ladders are hand-inlined. Not wrong today, since the parity pin guards the replica. But a freeze that lives in a comment is a freeze nobody enforces.
